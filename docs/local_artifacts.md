# Local Artifacts

These paths are local runtime state, generated output, or scratch space. They are not part of the source layout and should stay untracked.

| Path | Purpose | Notes |
| --- | --- | --- |
| `.env`, `.env.*` | Local secrets and provider keys | `.env.example` is the only env file meant to be committed. |
| `.tools/` | Downloaded local tool/model payloads | Can become large. Recreate by reinstalling the engine or voice/tool package. |
| `voice_packs/` | Local voice engine packs | Managed by the voice settings/install flow. |
| `data/` | Runtime analytics and local data output | If a new source artifact belongs in repo, put it under a named source package instead. |
| `memory/` | Daily local memory/log notes | `MEMORY.md` is also local runtime state and is ignored. |
| `temp/`, `tmp/`, `tmp_*`, `.tmp_*/` | Scratch files and generated test output | Safe to recreate. |
| `test_workspace/` | Manual and GPT tool test workspace | Tests may create files here while exercising file tools. |
| `agent_data/LOCAL_TOOLS.md` | Local private tool/context notes | Ignored; bundled runtime context lives in `runtime_context/`. |
| `.pytest_cache/`, `.cache/`, `.mypy_cache/`, `.ruff_cache/` | Tool caches | Generated by local checks. |
| `SYSTEM_HEALTH_REPORT.md`, `WORK_IN_PROGRESS.md` | Local operator notes | Useful while working, but not product docs. |

Source files should live in named product areas such as `desktop_app/`, `app_backend/`, `desktop_runtime/`, `local_agent_runtime/`, `runtime_support/`, `shared/`, `scripts/`, or `docs/`. When a root folder starts collecting generated files, either ignore it here or move durable source content into a clearer package.
