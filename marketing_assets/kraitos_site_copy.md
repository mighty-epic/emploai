## Section: Why Kraitos Exists

LLMs can reason about work. Running that work on a live machine is a systems problem.

Kraitos focuses on the operator layer between the model and the computer: what the system can observe, which tools it can call, how it recovers when a path fails, and what evidence it leaves behind for the human owner.

## Section: Operator Loop

### Observe

Browser snapshots, screenshots, OCR, logs, and memory give the loop current state before it acts.

### Act

Kraitos can use file tools, shell commands, browser refs, a Chrome extension bridge, keyboard and mouse input, and scheduled jobs.

### Verify

Each step feeds evidence back into the loop so the system can continue, recover, or stop with a readable result.

## Section: Built For Self-Hosting

Kraitos is designed for people who want automation without surrendering the runtime.

- Plain Markdown memory.
- Explicit authorized user controls.
- Inspectable logs and screenshots.
- Local, remote, and VPS deployment paths.
- Telegram and desktop control surfaces.

## Section: Browser Automation Without Guesswork

Kraitos uses structured browser snapshots with stable references instead of relying only on raw coordinates. When standard browser automation is too brittle, a Chrome extension bridge can connect to a real session. When the DOM is not enough, OCR and desktop input remain available.

## FAQ

### Is Kraitos an autonomous employee?

No. Position it as a self-hosted operator layer. The point is controlled execution, observable state, and user-owned infrastructure.

### Why not just use Selenium?

Some tasks work with Selenium. Others need a real logged-in browser session, page-level refs, or desktop-level fallback. Kraitos keeps multiple control paths available in one loop.

### Where is memory stored?

The project uses human-readable memory files such as `MEMORY.md` and daily logs rather than hiding all state in an opaque service.

### What should I try first?

Download the Windows MSI from `kraitos.app`, then test a small browser task where you can inspect the logs and screenshots. Add the public repo link here once it passes verification.
